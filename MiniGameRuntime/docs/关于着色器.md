# 关于着色器

## 顶点着色器

~~~c++
const char* vertexShaderSource = R"glsl(

#version 330 core // 指定使用 GLSL 3.30，采用核心模式 core，通常与 OpenGL 3.3 核心上下文配合使用

layout(location = 0) in vec3 position;
layout(location = 1) in vec3 color;

uniform vec2 objectOffset;

out vec3 vertexColor;

void main()
{
    vec2 movePosition = position.xy + objectOffset;

    gl_Position = vec4(movePosition, position.z, 1.0);
    vertexColor = color;
}
)glsl";
~~~

这段顶点着色器主要做两件事：**把顶点沿 x、y 方向平移，并把顶点颜色传递给后续渲染阶段。**

最外层是 C++ 代码，字符串里面才是 GLSL 着色器代码。下面按顺序解释。

1. **`const char\* vertexShaderSource = R"glsl(`**

   定义一个 C++ 字符串指针 `vertexShaderSource`，用来保存着色器的源代码。

   `R"glsl(... )glsl"` 是 C++ 的**原始字符串字面量**，可以直接包含多行文字，不需要把换行写成 `\n`。其中 `glsl` 是自定义的分隔标记，并不是关键字。

2. **`#version 330 core`**

   指定使用 **GLSL 3.30**，采用核心模式 `core`，通常与 OpenGL 3.3 核心上下文配合使用。

3. **`layout(location = 0) in vec3 position;`**

   声明一个 `vec3` 类型的输入变量 `position`，它的输入属性编号是 `0`

   表示意思：从“0 号输入口”接收当前顶点的三个数字，把它们叫作 `position`，后面用它们计算顶点的位置

   GLSL 中声明“顶点输入变量”的写法

   声明一个名为 `position` 的顶点输入变量：

   - `layout(location = 0)`：该属性使用编号为 `0` 的输入位置，需要与 C++ 端的顶点属性配置对应。
   - `in`：表示输入数据。
   - `vec3`：包含三个浮点数，通常分别表示顶点的 `x、y、z` 坐标。

   顶点着色器处理每个顶点时，会读取该顶点对应的 `position`。

4. **`layout(location = 1) in vec3 color;`**

   同上

   声明另一个顶点输入变量 `color`，使用编号为 `1` 的输入位置。

   它同样是 `vec3`，通常用三个分量表示红、绿、蓝，例如：

   ```
   vec3(1.0, 0.0, 0.0) // 红色
   ```

   每个顶点都可以拥有不同的颜色。

   CPU 上的 C++ 程序
       │ 准备位置、颜色数据
       ↓
   上传到顶点缓冲区
       │
       ↓ GPU 按配置自动读取
       ├── 属性 0：(0.2, 0.5, 0.0) → position
       └── 属性 1：(1.0, 0.0, 0.0) → color
                                         │
                                         ↓
                               顶点着色器进行计算

5. **`uniform vec2 objectOffset;`**

   声明一个二维浮点向量 `objectOffset`，用于控制平移：

   通常表示objectOffset增量

   ```
   objectOffset.x // 水平方向的偏移
   objectOffset.y // 垂直方向的偏移
   ```

   `uniform` 表示它是由 C++ 程序设置的参数，在一次绘制中，各个顶点共用同一个值。因此，所有顶点可以一起移动，形成整个物体的平移。

6. **`out vec3 vertexColor;`**

   声明一个名为 `vertexColor` 的输出变量，用来把颜色传给后续着色器阶段。

   在常见的“顶点着色器 → 片元着色器”流程中，片元着色器可以用对应的输入接收它：

   ```
   in vec3 vertexColor;
   ```

7. **`void main()`**

   定义着色器的入口函数。

   - `void`：函数不通过 `return` 返回值。
   - `main`：着色器开始执行的位置。
   - `()`：没有函数参数；输入来自前面声明的变量。

8. **`{`**

   表示 `main` 函数体开始。

9. **`vec2 movePosition = position.xy + objectOffset;`**

   计算平移后的二维位置：

   - `position.xy`：取出 `position` 的 `x、y` 两个分量，得到一个 `vec2`。
   - `+ objectOffset`：分别给 x、y 加上对应的偏移量。
   - `movePosition`：保存计算结果。

   等价于：

   ```
   vec2 movePosition = vec2(
       position.x + objectOffset.x,
       position.y + objectOffset.y
   );
   ```

   例如：

   ```
   position.xy  = vec2(0.2, 0.3);
   objectOffset = vec2(0.1, -0.2);
   ```

   那么 `movePosition` 就是 `(0.3, 0.1)`，即向右、向下移动。

10. **`gl_Position = vec4(movePosition, position.z, 1.0);`**

    将最终的顶点位置写入 GLSL 内置输出变量 `gl_Position`。它保存的是**裁剪空间坐标**，必须是四维向量 `vec4`。

    第四个 **`1.0` 是 `w` 的值**。`w` 用于后续的位置换算：渲染管线会把 x、y、z 分别除以 w，这一步叫“透视除法”

    这里的四个分量分别是：

    ```
    vec4(
        movePosition.x, // 平移后的 x
        movePosition.y, // 平移后的 y
        position.z,     // 保留原来的 z
        1.0             // 齐次坐标 w
    )
    ```

    后续管线会用 `x、y、z` 分别除以 `w`。这里 `w = 1.0`，所以除法不会改变它们的数值。

    这段代码没有使用变换矩阵，而是直接把计算结果作为裁剪空间位置输出。

    GLSL 已经预先定义好了 `gl_Position`，你只需要给它赋值

11. **`vertexColor = color;`**

    把当前顶点输入的颜色 `color`，复制给输出变量 `vertexColor`。

    如果绘制的是三角形，在默认设置下，光栅化阶段会对三个顶点的颜色进行插值，使三角形内部可以呈现平滑的颜色渐变。

12. **`}`**

    表示 `main` 函数体结束。

13. **`)glsl";`**

    这是外层 C++ 代码：

    - `)glsl"`：结束原始字符串，与开头的 `R"glsl(` 对应。
    - `;`：结束 C++ 变量定义语句。

注意：这里的 `objectOffset` **不是以像素为单位**。在当前 `w = 1.0` 的写法中，屏幕左右边界对应的 x 通常是 `-1` 和 `1`；因此 x 偏移 `0.1`，相当于向右移动视口宽度的约 `5%`。

## Q&A

1.为什么着色器代码用char指针来保存？

char*只保存起始地址，而根据起始地址完全可以找到着色器的代码，当然string\*也可以，char\*是一般写法。

2.R"glsl(... )glsl" 是什么写法？

原始字符串字面量，适合保存多行代码或包含大量引号、反斜杠的文本。

其中：

- **`R`**：表示使用原始字符串。
- **`glsl`**：自定义的分隔标记，前后必须一致。
- **括号之间的内容**：实际保存的字符串。

`glsl` 不是 C++ 关键字，也不会让 C++ 自动识别着色器语言。换成其他名字也可以，它最大的方便是：**换行、双引号和反斜杠可以直接写，不需要转义**

## 片段着色器

~~~c++
const char* fragmentShaderSource = R"glsl(
#version 330 core

in vec3 vertexColor;

out vec4 fragmentColor;

void main()
{
    fragmentColor = vec4(vertexColor, 1.0);
}
)glsl";
~~~

同样的现在我们来解释这段片段着色器：fragmentShaderSource是用char指针来保存的首地址。in vec3 vertexColor;是接收的上面顶点着色器的out vec3 vertexColor;同时自己输出out vec4 fragmentColor;在主函数中变量fragmentColor是一个vec4变量，前三个是vertexColor的值，最后一个是1表示是 Alpha 值，完全不透明。

## 编译顶点着色器

~~~c++
    GLuint vertexShader = glCreateShader(GL_VERTEX_SHADER); // 创建顶点着色器对象

    glShaderSource( // 把源代码交给着色器对象
        vertexShader,
        1,
        &vertexShaderSource,
        nullptr
    );

    glCompileShader(vertexShader); //编译GPU程序 这是编译GLSL着色器，不是编译C++
~~~

**GLuint vertexShader = glCreateShader(GL_VERTEX_SHADER);**

这行创建一个顶点着色器对象。

- **`glCreateShader(...)`**：OpenGL 提供的创建着色器对象的函数。
- **`GL_VERTEX_SHADER`**：指定创建的是“顶点着色器”。
- **`GLuint`**：OpenGL 定义的无符号整数类型。
- **`vertexShader`**：保存返回的对象编号，后续通过这个编号操作该着色器。

可以理解为：**先创建一个着色器对象，再拿到它的编号。** 这时还没有提供代码，也没有编译。

~~~c++
glShaderSource(
    vertexShader,
    1,
    &vertexShaderSource,
    nullptr
);
~~~

| 参数                  | 含义                                                   |
| --------------------- | ------------------------------------------------------ |
| `vertexShader`        | 把源码交给哪个着色器对象                               |
| `1`                   | 本次提供几个源码字符串，这里只有一个                   |
| `&vertexShaderSource` | 提供源码字符串指针的地址，这里指向之前创建的顶点着色器 |
| `nullptr`             | 不单独指定字符串长度，由 OpenGL 根据结尾的 `'\0'` 判断 |

`vertexShaderSource` 保存着字符串的起始地址；`&vertexShaderSource` 则是**这个指针变量自身的地址**

~~~c++
glCompileShader(vertexShader);
~~~

这一步是**请求 OpenGL 驱动编译该对象中保存的 GLSL 源代码**，编译GLSL着色器
